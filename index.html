Guía Definitiva Vercel Skills (npx skills)

Tutorial paso a paso para principiantes. Aprenderás qué es Vercel Skills, cómo instalar la herramienta, cómo crear tu primera habilidad y cómo evitar los errores más habituales — sin necesidad de conocimientos técnicos previos.

¿Qué vas a conseguir?

  • Entender el problema que resuelve npx skills.
  • Verificar tu entorno (Node.js y Git).
  • Buscar, instalar, listar, actualizar y eliminar habilidades.
  • Crear tu propio archivo SKILL.md desde cero.
  • Diagnosticar los fallos más frecuentes.

¿A quién va dirigido?

A cualquier persona que use (o quiera usar) asistentes de programación con IA y quiera dejar de mantener cinco archivos de reglas distintos. No hace falta saber programar, pero sí es necesario poder abrir una terminal y escribir comandos.

Conocimientos previos: ninguno técnico. Solo familiaridad básica con archivos y carpetas.

Conceptos fundamentales

Antes de escribir un solo comando, necesitas entender qué problema resuelve esta herramienta. Esta sección va de lo general a lo concreto.

1. El problema: cada agente habla su propio idioma

En el desarrollo de software asistido por inteligencia artificial, el ecosistema de herramientas ha crecido muy rápido. Ese crecimiento ha traído consigo una fragmentación evidente: cada agente de codificación o entorno de desarrollo integrado (IDE) suele requerir su propia forma de configurar instrucciones personalizadas.

Imagina un equipo multidisciplinario. La arquitectura del proyecto exige que cada API consulte primero un esquema de validación estricto. Para que todos los asistentes lo respeten, el equipo debe escribir y mantener a mano:

ArchivoHerramienta que lo lee
.cursorrulesCursor
CLAUDE.mdClaude Code
.copilot-instructions.mdGitHub Copilot
.windsurfrulesWindsurf

Cada vez que la regla de arquitectura evoluciona, el desarrollador debe actualizar individualmente cuatro o cinco archivos distintos, con sintaxis y formatos heterogéneos. El resultado es siempre el mismo: fricción, duplicación de esfuerzos y desalineación entre los miembros del equipo.

Interoperabilidad entre agentes

Es la capacidad de definir un conjunto reutilizable de instrucciones operativas en un formato estandarizado, para que cualquier agente de inteligencia artificial —sin importar su fabricante o su interfaz— pueda interpretarlo y ejecutarlo sin necesidad de reescrituras específicas.

2. ¿Qué es Vercel Skills (npx skills)?

Vercel Skills (npx skills) es la herramienta CLI (Interfaz de Línea de Comandos) de código abierto diseñada para servir como el motor universal del ecosistema de habilidades de agentes (Agent Skills).

3. ¿Qué es una «Skill» (habilidad)?

Una Skill es un paquete reutilizable de instrucciones operativas definido dentro de un archivo SKILL.md. Ese archivo incluye un encabezado en formato YAML (frontmatter) con dos campos obligatorios: name y description.

Gracias a estas habilidades, los agentes de IA pueden realizar tareas altamente especializadas y adaptadas a los estándares de un equipo o proyecto concreto.

Los tres casos de uso principales de la documentación oficial

Caso de usoQué permite
Generación de notas de lanzamiento (release notes)Extraer e interpretar el historial de transacciones de Git para redactar resúmenes estructurados de cambios.
Creación de Solicitudes de Extracción (Pull Requests)Formatear y enviar PRs siguiendo estrictamente las convenciones estandarizadas del equipo de desarrollo.
Integración con herramientas externasPermitir que los agentes interactúen con servicios y plataformas de terceros como Linear, Notion, entre otros.

Estas habilidades pueden ser descubiertas, inspeccionadas e instaladas desde el directorio centralizado en skills.sh.

5. Requisitos previos del sistema

Para garantizar un funcionamiento correcto de la CLI de skills, el sistema operativo debe cumplir estrictamente con estas dependencias:

  1. Node.js: se requiere de manera obligatoria la versión 22.20 o superior.
  2. npx: incluido por defecto con la instalación de Node.js.
  3. Git: debe estar instalado y accesible globalmente en la variable de entorno del sistema.

Para verificar si el entorno cuenta con las versiones adecuadas, ejecuta los siguientes comandos en la terminal:

# Verificar la versión de Node.js (debe ser >= 22.20)
node -v

# Verificar la versión de Git
git --version

6. Autenticación para repositorios privados y API de GitHub

La CLI utiliza una jerarquía de autenticación estructurada para resolver el acceso a repositorios tanto públicos como privados.

6.1. Credenciales para accesos HTTPS y shorthand (owner/repo)

  1. Credenciales Git estándar: la CLI intenta primero utilizar el Git credential helper configurado localmente en el sistema.
  2. GitHub CLI (gh): si el paso anterior falla y la herramienta GitHub CLI está instalada y autenticada, ejecuta la clonación mediante gh repo clone o llamadas a la API mediante gh api.
  3. Fallback a SSH: si fallan las opciones de HTTPS, la CLI intenta autenticarse mediante protocolos SSH (git@github.com:... o ssh://git@...).

6.2. Evaluación de la API de GitHub para búsqueda de árboles (Tree Lookups)

  1. Intenta primero una solicitud anónima a la API de GitHub.
  2. Si es rechazada por límites de tasa o permisos, evalúa las variables de entorno GITHUB_TOKEN o GH_TOKEN.
  3. Si no existen tokens en el entorno, ejecuta de forma delegada gh api.
  4. Si el acceso a la API sigue fallando, las comprobaciones de actualización recurren a una clonación Git autenticada.
Garantía de seguridad e integridad de credenciales La CLI nunca ejecuta gh auth token ni copia credenciales almacenadas dentro del proceso de Node.js. Las llamadas delegadas a gh api devuelven únicamente la respuesta obtenida, sin exponer ni imprimir credenciales en pantalla.

7. Detección automática de agentes compatibles

Al ejecutar comandos de instalación por primera vez, la CLI realiza un escaneo del sistema local para identificar cuáles de los más de 75 agentes compatibles se encuentran instalados en el equipo del usuario.

Nota Si la CLI no detecta ningún agente activo durante la ejecución, mostrará automáticamente un menú interactivo solicitando al usuario que seleccione manualmente los agentes de IA a los que desea vincular las habilidades.

8. Ámbitos de aplicación (scopes): proyecto vs. global

Al instalar habilidades se puede elegir entre un ámbito local restringido a un proyecto específico o un ámbito global disponible para todo el usuario en el sistema.

ÁmbitoFlagRuta predeterminadaCaso de uso recomendado
Proyecto(Predeterminado).//skills/Habilidades específicas compartidas con el equipo de desarrollo e incluidas en el control de versiones (Git).
Global-g / --global~//skills/Herramientas personales de utilidad general disponibles para el desarrollador en cualquier proyecto local.
Nota de fidelidad al documento fuente El documento original muestra estas rutas con una barra duplicada (.//skills/ y ~//skills/), lo que parece un artefacto de formato. Se reproducen tal cual para no alterar la fuente. La salida de ejemplo del propio documento sí muestra ~/.skills/canonical/ como almacén canónico de las habilidades.

9. Métodos de instalación: enlace simbólico vs. copia directa

Durante la instalación interactiva o mediante flags, la CLI ofrece dos mecanismos para posicionar las habilidades dentro de las rutas de los agentes.

Enlace simbólico (symlink) — método recomendado

Qué hace: crea un enlace simbólico desde el directorio de cada agente hacia una copia canónica centralizada en el sistema.

Ventajas: funciona como una fuente única de verdad (single source of truth), permitiendo actualizar la habilidad una sola vez para que el cambio se refleje automáticamente en todos los agentes configurados.

Cuándo usarlo: entornos de desarrollo locales donde se utilizan múltiples agentes de IA de forma simultánea.

Copia directa (--copy)

Qué hace: copia físicamente los archivos dentro de la estructura de cada agente, de manera independiente.

Ventajas: no depende de enlaces simbólicos.

Cuándo usarlo: sistemas de archivos o entornos corporativos donde los enlaces simbólicos están restringidos por políticas de seguridad o no son soportados por el sistema operativo.

Conexión con el siguiente paso Habiendo definido los ámbitos y métodos de almacenamiento, la siguiente sección aborda en detalle el repertorio completo de comandos que ofrece la CLI.

10. Comparativa: Vercel Skills vs. MCP vs. reglas directas

Es fundamental comprender la frontera de responsabilidades entre estas tecnologías.

  • Model Context Protocol (MCP) es un protocolo de comunicación cliente-servidor diseñado para la ejecución de herramientas y conexión a fuentes de datos externalizadas (bases de datos, APIs de terceros, entornos de ejecución).
  • Vercel Skills proporciona instrucciones contextuales y prompts de flujo de trabajo estandarizados, portables y reutilizables entre múltiples agentes.
  • Las reglas directas (.cursorrules, CLAUDE.md) son archivos de instrucciones locales acoplados a un software específico.
CriterioVercel Skills (npx skills)MCP / Reglas directas
Propósito principalEcosistema abierto de habilidades e instrucciones ejecutables portables entre agentes.MCP conecta herramientas y servidores de datos; las reglas directas definen instrucciones locales para un solo agente.
PortabilidadAlta: una única habilidad funciona en más de 75 agentes mediante el estándar agentskills.io.Baja: los archivos de reglas directas están acoplados al agente o IDE específico que los interpreta.
Distribución y gestiónInstalación, actualización y eliminación centralizada y automatizada vía CLI (npx skills).Copia e inclusión manual de archivos en cada repositorio o configuración de entorno.

Procedimiento paso a paso

Cada paso indica objetivo, acción, por qué se hace y resultado esperado. Haz una sola cosa cada vez y comprueba el resultado antes de continuar.

Antes de empezar Todos los comandos se escriben en una terminal (en Windows: PowerShell o Símbolo del sistema; en macOS/Linux: Terminal) y se ejecutan pulsando Enter. No escribas el símbolo $ ni #: en los ejemplos, # indica un comentario explicativo.
Paso 0

Abrir la terminal en la carpeta de tu proyecto

Objetivo: situarte en el lugar correcto antes de ejecutar nada.

Por qué importa: el ámbito de proyecto (el predeterminado) instala las habilidades relativas a la carpeta actual. Si abres la terminal en otro sitio, las habilidades acabarán en un proyecto equivocado.

  1. Abre la carpeta de tu proyecto en el explorador de archivos.
  2. Haz clic derecho sobre un espacio vacío de la carpeta.
  3. Elige «Abrir en Terminal» (Windows) o «Nuevo terminal en la carpeta» (macOS).
Resultado esperado: se abre una ventana de terminal cuyo texto termina en el nombre de tu carpeta de proyecto.
Paso 1

Verificar Node.js y Git

Objetivo: confirmar que el entorno cumple los requisitos mínimos.

Por qué importa: sin Node.js 22.20 o superior, y sin Git accesible globalmente, la CLI no funcionará correctamente.

  1. Escribe node -v y pulsa Enter.
  2. Escribe git --version y pulsa Enter.
node -v
git --version
Resultado esperado: la primera orden imprime un número de versión igual o superior a v22.20.x. La segunda imprime algo como git version 2.x.x.
¿Y si sale «no se reconoce como un comando»?

Significa que Node.js o Git no están instalados, o que no están en el PATH del sistema. Instálalos desde sus sitios oficiales, cierra la terminal y vuelve a abrirla. Después repite el paso 1.

Si la versión de Node.js es inferior a 22.20, actualízala antes de continuar.

Paso 2

Buscar habilidades con find

Objetivo: descubrir qué habilidades existen antes de instalar nada.

Por qué importa: find explora catálogos alojados en la plataforma skills.sh o en repositorios específicos de usuarios y organizaciones.

  1. Ejecuta el comando de búsqueda interactiva (interfaz de selección estilo fzf).
  2. O busca por palabra clave concreta.
  3. O busca globalmente dentro de un usuario u organización.
# Búsqueda interactiva basada en interfaz de selección estilo fzf
npx skills find

# Búsqueda por palabra clave específica
npx skills find typescript

# Búsqueda global en repositorios pertenecientes a un usuario u organización
npx skills find react --owner vercel
Resultado esperado: aparece una lista de habilidades coincidentes (o un selector interactivo si no se especifica palabra clave).
Paso 3

Inspeccionar un catálogo sin instalar

Objetivo: ver qué contiene un repositorio antes de tocar tu proyecto.

Por qué importa: la bandera -l / --list muestra el catálogo de habilidades disponibles en la fuente sin instalarlas.

npx skills add vercel-labs/agent-skills --list
Resultado esperado: un listado con el nombre y la descripción de cada habilidad disponible en ese repositorio. Nada se instala.
Paso 4

Instalar una habilidad con add

Objetivo: importar la habilidad elegida y vincularla a los agentes que uses.

Por qué importa: add es el motor principal de importación y acepta orígenes muy distintos.

Formatos de origen admitidos

Formato de origenEjemplo de comando
Shorthand de GitHubnpx skills add vercel-labs/agent-skills
URL completa de GitHubnpx skills add https://github.com/vercel-labs/agent-skills
Ruta a un subdirectorionpx skills add https://github.com/vercel-labs/agent-skills/tree/main/skills/web-design-guidelines
GitLab URLnpx skills add https://gitlab.com/org/repo
Azure Reposnpx skills add https://dev.azure.com/org/project/_git/repo
Azure Repos con ruta/versiónnpx skills add https://dev.azure.com/org/project/_git/repo?path=/skills/web-design&version=GBmain
URL de Git pura (SSH)npx skills add git@github.com:vercel-labs/agent-skills.git
Ruta localnpx skills add ./my-local-skills
URL de descarga directanpx skills add https://example.com/download/my-skill
Diferencia técnica entre --skill y @ En el comando add, la selección explícita de habilidades dentro de un repositorio se realiza mediante la bandera -s o --skill (por ejemplo npx skills add vercel-labs/agent-skills --skill web-design-guidelines). El delimitador @ (por ejemplo owner/repo@skill-name) es una sintaxis abreviada utilizada prioritariamente por el comando use para identificar y resolver una habilidad específica dentro de una fuente, en ejecuciones efímeras.

Banderas y opciones avanzadas de add

Opción / FlagDescripción
-g, --globalInstala en el directorio de usuario global (~/) en lugar del proyecto actual.
-a, --agentEspecifica los agentes destino (por ejemplo claude-code, cursor). Utiliza '*' para todos.
-s, --skillEspecifica el nombre exacto de la habilidad a instalar. Utiliza '*' para todas.
-l, --listMuestra el catálogo de habilidades disponibles en la fuente sin instalarlas.
--copyFuerza la copia física de los archivos evitando la creación de enlaces simbólicos (symlinks).
-y, --yesOmite todas las preguntas interactivas de confirmación.
--allInstala todas las habilidades encontradas hacia todos los agentes detectados sin prompts.

Ejemplos prácticos de combinación de parámetros

# 1. Combinación compleja: instalación global, no interactiva, con copia física para un agente específico
npx skills add vercel-labs/agent-skills --skill web-design-guidelines -g -a claude-code --copy -y

# 2. Instalar una habilidad cuyo nombre contiene espacios (requiere comillas obligatorias)
npx skills add owner/repo --skill "Convex Best Practices"

# 3. Instalación de múltiples habilidades hacia múltiples agentes de forma explícita
npx skills add vercel-labs/agent-skills -s frontend-design -s skill-creator -a claude-code -a opencode

# 4. Instalar todas las habilidades de un repositorio hacia todos los agentes del sistema
npx skills add vercel-labs/agent-skills --all

# 5. Instalar habilidades específicas filtrando agentes mediante el comodín '*'
npx skills add vercel-labs/agent-skills --skill frontend-design --agent '*'
Resultado esperado: la CLI descarga la fuente, crea los enlaces (o copias) en las carpetas de cada agente y muestra un mensaje de éxito por cada agente vinculado.
Paso 5

Verificar lo instalado con list

Objetivo: confirmar la ruta exacta donde ha quedado cada habilidad.

Por qué importa: si un agente no responde a la habilidad, casi siempre se debe a que se instaló en una ruta que ese agente no lee.

  1. Lista las habilidades instaladas localmente en el proyecto actual.
  2. O lista únicamente las instaladas a nivel global.
  3. O filtra el listado por agentes concretos.
# --- LISTAR HABILIDADES (alias: ls) ---
# Listar habilidades instaladas localmente en el proyecto actual
npx skills list

# Listar únicamente habilidades instaladas a nivel global
npx skills ls -g

# Filtrar el listado por agentes específicos
npx skills ls -a claude-code -a cursor
Resultado esperado: un árbol de rutas con el nombre de cada habilidad y, entre paréntesis, si es un symlink y hacia dónde apunta.
Paso 6

Probar sin instalar: uso efímero con use

Objetivo: ejecutar una habilidad al vuelo sin alterar la configuración del entorno local.

Por qué importa: use escribe la habilidad seleccionada en un directorio temporal y emite el prompt resultante directamente hacia stdout. Nada permanente queda en tu proyecto.

  1. Genera el prompt con la sintaxis de delimitación @ y canalízalo (pipe) a Claude CLI.
  2. O inicia un agente interactivo especificando habilidad y agente mediante banderas.
# Generar el prompt con la sintaxis de delimitación '@' y canalizarlo (pipe) a Claude CLI
npx skills use vercel-labs/agent-skills@web-design-guidelines | claude

# Iniciar un agente interactivo especificando habilidad y agente mediante banderas
npx skills use vercel-labs/agent-skills --skill web-design-guidelines --agent claude-code
Resultado esperado: la CLI indica que ha escrito la habilidad en un directorio temporal y lanza el agente con ese contexto de prompt.
Paso 7

Actualizar habilidades con update

Objetivo: traer la última versión de las habilidades ya instaladas.

Por qué importa: con el método de enlace simbólico, actualizar una sola vez propaga el cambio a todos los agentes vinculados.

# --- ACTUALIZAR HABILIDADES ---
# Actualizar interactivamente todas las habilidades instaladas
npx skills update

# Actualizar habilidades específicas por su nombre
npx skills update frontend-design web-design-guidelines

# Actualizar forzando ámbito global (-g) o ámbito de proyecto (-p)
npx skills update -g
npx skills update -p

# Modo no interactivo (auto-detecta: proyecto si existe directorio de proyecto, si no global)
npx skills update -y
Resultado esperado: un resumen por habilidad indicando si se ha actualizado o si ya estaba al día.
Paso 8

Eliminar habilidades con remove / rm

Objetivo: desvincular una habilidad de un agente concreto o retirar todas las globales.

Por qué importa: eliminar es la operación más delicada; conviene hacerla de forma dirigida, no masiva, salvo que estés seguro.

# --- ELIMINAR HABILIDADES (alias: rm) ---
# Eliminar una habilidad específica de un agente determinado
npx skills remove web-design-guidelines --agent claude-code

# Eliminar todas las habilidades instaladas a nivel global de forma no interactiva
npx skills rm --all -g
Resultado esperado: confirmación de qué habilidades se han eliminado y de qué agentes.
Paso 9

Crear una plantilla con init

Objetivo: generar la estructura base de tu propia habilidad.

Por qué importa: evita empezar desde un archivo vacío y reduce los errores de formato YAML.

  1. Para crear un archivo de plantilla SKILL.md en la raíz del directorio actual, ejecuta npx skills init.
  2. Para crear un subdirectorio con una nueva plantilla lista para editar, pasa un nombre: npx skills init mi-primera-skill.
# Crear un archivo de plantilla SKILL.md en la raíz del directorio actual
npx skills init

# Crear un subdirectorio con una nueva plantilla de habilidad lista para editar
npx skills init mi-primera-skill
Resultado esperado: aparece un mensaje de plantilla inicializada y, en la segunda variante, una carpeta mi-primera-skill/ con un archivo SKILL.md dentro.
Paso 10

Editar el archivo SKILL.md

Objetivo: convertir la plantilla en una habilidad real y comprensible para el agente.

Por qué importa: es el corazón de todo el sistema. Un archivo mal formado no será detectado.

El estándar Agent Skills

Todas las habilidades de este ecosistema se construyen bajo la especificación Agent Skills (accesible en agentskills.io). Este estándar garantiza que el cuerpo de instrucciones sea perfectamente legible y ejecutable por cualquier modelo o agente de IA, sin importar su arquitectura subyacente.

Estructura del encabezado (YAML frontmatter)

El archivo SKILL.md debe comenzar de forma obligatoria, en la primera línea, con un bloque de encabezado YAML delimitado por ---.

---
name: nombre-de-la-skill
description: Explicación breve de lo que hace la habilidad y cuándo activarla
metadata:
  internal: false
---
  • name (obligatorio): identificador único de la habilidad. Debe estar escrito estrictamente en minúsculas y separado por guiones (formato kebab-case).
  • description (obligatorio): descripción clara de las capacidades de la habilidad. Este texto es evaluado por el agente de IA para determinar cuándo debe activar la habilidad.
  • metadata.internal (opcional): si se establece en true, oculta la habilidad en las búsquedas y exploraciones normales. Solo se mostrará e instalará cuando la variable de entorno INSTALL_INTERNAL_SKILLS=1 esté presente en la sesión.

Estructura canónica recomendada del cuerpo

---
name: guias-de-estilo
description: Aplica las reglas de diseño y arquitectura de código del proyecto.

# Guías de Estilo de Código

Instrucciones generales que el agente debe seguir obligatoriamente cuando esta habilidad esté activa.

## When to Use

Descubrimiento de habilidades y layouts de catálogo

Al escanear un repositorio, la CLI inspecciona las rutas hasta una profundidad máxima de 3 niveles en esquemas planos o de catálogo.

Patrones de estructura soportados

  • Diseño plano (nivel 1): skills/<nombre>/SKILL.md
  • Catálogo de 1 categoría (nivel 2): skills/<categoría>/<nombre>/SKILL.md
  • Catálogo de 2 categorías (nivel 3): skills/<categoría>/<subcategoría>/<nombre>/SKILL.md

Carpetas contenedoras evaluadas por defecto

  • Directorio raíz (si contiene directamente un archivo SKILL.md).
  • Carpetas estándar: skills/, skills/.curated/, skills/.experimental/, skills/.system/.
  • Rutas específicas de agentes: .agents/skills/, .claude/skills/, .cursor/skills/, .kiro/skills/, data/skills/, .autohand/skills/, .augment/skills/, .bob/skills/, .codebuddy/skills/, .commandcode/skills/, .continue/skills/, .devin/skills/, agent/skills/, .goose/skills/, .hermes/skills/, .openhands/skills/, .roo/skills/, .windsurf/skills/, .zencoder/skills/, entre otras.

Regla de ensombrecimiento (shadowing)

Un archivo SKILL.md descubierto en un nivel superficial anula o enmascara cualquier habilidad anidada a mayor profundidad que comparta exactamente el mismo nombre.

Otras opciones de descubrimiento

  • --full-depth: permite forzar la búsqueda de archivos SKILL.md ubicados fuera de las carpetas contenedoras estándar (por ejemplo, dentro de directorios como examples/ o tests/).
  • Manifiestos de plugins: si existen archivos .claude-plugin/marketplace.json o .claude-plugin/plugin.json, las habilidades declaradas en ellos son descubiertas respetando la ruta definida en la propiedad pluginRoot. Estas rutas declaradas no están sujetas al límite de 3 niveles de profundidad.

Umbrales y límites de seguridad en descargas

Para prevenir ataques de denegación de servicio o la extracción desproporcionada de paquetes maliciosos (zip bombs) al descargar fuentes desde URLs directas, la CLI aplica estas salvaguardas por defecto:

  • Límite máximo de descarga: 10 MiB (modificable con SKILLS_DOWNLOAD_MAX_BYTES).
  • Límite máximo de extracción: 25 MiB (modificable con SKILLS_EXTRACT_MAX_BYTES).
  • Límite de cantidad de archivos: 1000 archivos (modificable con SKILLS_EXTRACT_MAX_FILES).

Auditoría de seguridad y telemetría

La CLI recolecta datos anónimos de uso para mejorar la herramienta. No se recopila ninguna información personal del desarrollador.

Atención Los identificadores de repositorios y habilidades en GitHub solo se transmiten a los servidores de telemetría si GitHub confirma positivamente que el repositorio es público. Para otros servidores o remotos Git (como GitLab o Azure DevOps), la visibilidad no se puede validar mediante la API de GitHub, por lo que los identificadores de instalación podrían incluirse en la telemetría general. Las solicitudes de auditoría de seguridad automatizada permanecen estrictamente limitadas a repositorios de GitHub confirmados como públicos.

Para desactivar por completo cualquier transmisión de datos en la sesión actual de terminal:

export DISABLE_TELEMETRY=1

Caso especial: Kiro CLI

El agente Kiro CLI detecta y carga de forma automática las habilidades ubicadas en .kiro/skills/ y ~/.kiro/skills/. Sin embargo, si se utiliza un agente personalizado dentro de Kiro, es necesario declarar explícitamente el recurso dentro de su archivo de configuración .kiro/agents/<nombre>.json:

{
  "resources": [
    "skill://.kiro/skills/**/SKILL.md"
  ]
}

Patrón estándar de carpeta compartida

Agentes como Cursor, GitHub Copilot, OpenCode, Codex, Cline, Zed y Warp comparten el directorio estándar de proyecto .agents/skills/, lo que permite que una sola instalación local funcione simultáneamente para todos ellos sin duplicar archivos.

Ejercicios con solución

Ejercicio 1 — Instalación global y silenciosa con copia física

Enunciado: instala la habilidad web-design-guidelines del repositorio vercel-labs/agent-skills en el ámbito global, solo para claude-code, forzando copia física y sin preguntas interactivas.

Solución:

npx skills add vercel-labs/agent-skills --skill web-design-guidelines -g -a claude-code --copy -y

Por qué: -g aplica el ámbito global, -a claude-code restringe el agente, --copy evita los enlaces simbólicos y -y omite las confirmaciones. La habilidad se selecciona con --skill, no con @ (el delimitador @ es propio del comando use).

Ejercicio 2 — Instalar una habilidad con espacios en el nombre

Enunciado: instala la habilidad llamada Convex Best Practices desde owner/repo.

Solución:

npx skills add owner/repo --skill "Convex Best Practices"

Por qué: cuando el nombre contiene espacios, las comillas son obligatorias. Sin ellas, la terminal interpretaría cada palabra como un argumento distinto.

Ejercicio 3 — Ejecutar una habilidad sin dejar rastro

Enunciado: prueba la habilidad web-design-guidelines de vercel-labs/agent-skills con el agente claude-code sin escribir archivos permanentes en el proyecto.

Solución:

npx skills use vercel-labs/agent-skills --skill web-design-guidelines --agent claude-code

Por qué: use escribe la habilidad en un directorio temporal y emite el prompt resultante, sin alterar la configuración del entorno local.

Ejercicio 4 — Diagnosticar una habilidad que no se detecta

Enunciado: has creado mi-habilidad/SKILL.md dentro de examples/ y la CLI responde «No skills found». ¿Qué haces?

Solución: la carpeta examples/ no está entre las carpetas contenedoras estándar, y la CLI solo inspecciona hasta 3 niveles de profundidad en las rutas reconocidas. Añade la bandera --full-depth al comando para forzar la búsqueda fuera de esas carpetas:

npx skills add ./examples --full-depth

Antes de eso, verifica también que el encabezado YAML empiece en la primera línea y que contenga name y description.

Lista de comprobación de la práctica

Diagnóstico de problemas y errores frecuentes

A pesar de la alta compatibilidad de la CLI, pueden surgir imprevistos durante la instalación o la ejecución. Aquí tienes los cinco casos documentados, con síntoma, causa probable y solución paso a paso.

Error 1 — «No skills found» durante la instalación

Síntoma: la CLI analiza el repositorio o la ruta proporcionada, pero informa que no se encontraron habilidades.

Causa probable: el archivo SKILL.md no existe dentro de las rutas de contenedor escaneadas, o el encabezado YAML (frontmatter) carece de las claves obligatorias name o description.

Solución paso a paso:

  1. Abre el archivo SKILL.md objetivo en tu editor.
  2. Verifica que el encabezado comience estrictamente en la primera línea del archivo con los tres guiones ---.
  3. Confirma que las propiedades name: y description: estén presentes y bien formateadas.
  4. Si la habilidad está ubicada en un directorio profundo fuera de las carpetas estándar, ejecuta el comando añadiendo la bandera --full-depth.

Error 2 — La habilidad no se carga ni aparece dentro del agente de IA

Síntoma: la CLI confirma la instalación exitosa, pero el agente de IA no responde a las instrucciones de la habilidad.

Causa probable: archivos ubicados en una ruta no leída por el agente, o sintaxis YAML no válida en el encabezado.

Solución paso a paso:

  1. Ejecuta npx skills list para confirmar la ruta exacta donde fue instalada la habilidad.
  2. Valida que tu agente de IA esté configurado para leer el directorio del proyecto (por ejemplo .agents/skills/ o .claude/skills/).
  3. Para usuarios de Kiro CLI con agentes personalizados, confirma que el recurso skill://.kiro/skills/**/SKILL.md esté declarado en el archivo JSON del agente.

Error 3 — Fallos o permisos denegados al crear enlaces simbólicos

Síntoma: error del sistema operativo indicando permisos insuficientes al crear symlinks durante npx skills add.

Causa probable: políticas de seguridad del sistema de archivos local o restricciones de la cuenta de usuario.

Solución paso a paso:

  1. Ejecuta la instalación utilizando explícitamente el método de copia física agregando el parámetro --copy.
npx skills add vercel-labs/agent-skills --copy

Error 4 — Excedido el límite de tamaño o de archivos al descargar

Síntoma: la descarga desde una URL directa cancela la operación indicando que el paquete excede los límites permitidos.

Causa probable: el archivo comprimido supera los 10 MiB de descarga, los 25 MiB de extracción o los 1000 archivos por omisión.

Solución paso a paso:

  1. Si confías plenamente en la fuente, incrementa temporalmente los límites de la CLI anteponiendo las variables de entorno en la terminal.
SKILLS_DOWNLOAD_MAX_BYTES=52428800 SKILLS_EXTRACT_MAX_BYTES=104857600 npx skills add https://example.com/download/my-skill

Error 5 — Caracteres extraños o instrucciones ignoradas

Síntoma: el agente parece leer la habilidad, pero no aplica las reglas o las aplica de forma errática.

Causa probable: según las buenas prácticas documentadas, descripciones demasiado vagas, ausencia de disparadores explícitos o pasos redactados de forma ambigua.

Solución paso a paso:

  1. Reescribe description para que sea concisa e indique claramente el propósito.
  2. Detalla en When to Use los escenarios, extensiones de archivo o tareas concretas que deben desencadenar la habilidad.
  3. Redacta Steps como lista numerada, con verbos en imperativo o infinitivo, una sola acción por paso.

Resumen

Las cinco ideas clave

1. El problema

Cada agente exige su propio archivo de reglas. Mantener cuatro o cinco archivos con sintaxis distintas genera fricción y desalineación.

2. La solución

npx skills es una CLI en TypeScript, con licencia MIT, compatible con más de 75 agentes, que centraliza la gestión de habilidades.

3. La unidad

Una Skill es un archivo SKILL.md con frontmatter YAML. name y description son obligatorios.

4. El mecanismo

Los enlaces simbólicos crean una fuente única de verdad; --copy es la alternativa cuando los symlinks están restringidos.

5. El límite

El descubrimiento llega a 3 niveles de profundidad en carpetas reconocidas. --full-depth amplía la búsqueda.

Buenas prácticas

Descripciones semánticas, disparadores explícitos en When to Use y pasos secuenciales y deterministas.

Chuleta de comandos

# Descubrimiento
npx skills find
npx skills find typescript
npx skills find react --owner vercel

# Inspección sin instalar
npx skills add vercel-labs/agent-skills --list

# Instalación
npx skills add vercel-labs/agent-skills
npx skills add vercel-labs/agent-skills --skill web-design-guidelines -g -a claude-code --copy -y
npx skills add ./mi-primera-skill -a '*' -y
npx skills add vercel-labs/agent-skills --all

# Uso efímero
npx skills use vercel-labs/agent-skills@web-design-guidelines | claude
npx skills use vercel-labs/agent-skills --skill web-design-guidelines --agent claude-code

# Listado
npx skills list
npx skills ls -g
npx skills ls -a claude-code -a cursor

# Actualización
npx skills update
npx skills update frontend-design web-design-guidelines
npx skills update -g
npx skills update -p
npx skills update -y

# Eliminación
npx skills remove web-design-guidelines --agent claude-code
npx skills rm --all -g

# Inicialización
npx skills init
npx skills init mi-primera-skill

# Privacidad
export DISABLE_TELEMETRY=1

Buenas prácticas de diseño de SKILL.md

  1. Redactar descripciones semánticas y precisas: la propiedad description del frontmatter YAML es leída por el agente para evaluar si activa o no la habilidad. Debe ser concisa e indicar claramente el propósito.
  2. Establecer disparadores explícitos en When to Use: detalla con claridad los escenarios, extensiones de archivo o tareas de desarrollo específicas que deben desencadenar la aplicación de la habilidad.
  3. Estructurar los pasos de forma secuencial y determinista: define la sección Steps mediante listas numeradas redactadas con verbos en imperativo o infinitivo, para evitar ambigüedades durante la ejecución del agente.

Siguientes pasos

  • Explora el catálogo de skills.sh para descubrir habilidades ya publicadas.
  • Lee la especificación Agent Skills en agentskills.io para conocer el estándar completo.
  • Empaqueta las reglas de tu equipo en un SKILL.md y sustitúyelas por los archivos individuales de cada agente.
